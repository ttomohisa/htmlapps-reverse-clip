# Reverse Clip — 初回公開対象と受入条件（2026-10-17改訂案）

**状態：RC作業に適用する見直し案。正式な公開承認ではない。**
ユーザーの「厳しすぎる試験条件は必要なものを残して見直す」という指示に基づき、必要な安全確認と品質を維持しながら、対応を宣言しない端末・試験画質・全組合せの反復を初期リリースの必須条件から分離する。正式な対応プラットフォーム・公開可否はRCレビューで確定する。

## 公開対象の提案

- **主対象：Windows Chrome と Android Chrome。** Androidは実機の最新版で少なくとも一度、動画選択→編集→逆再生／往復再生→MP4保存・再生を確認する。ST単一HTML（Windows）と、サイト配信用の隔離されたMT版（Android）はそれぞれ検査する。
- **対応を表明できる入力：実際に検証したH.264 MP4。** H.264 MOV・VFR・回転はデスクトップChromeで実証済みの組合せを注記。HEVC MOV、HDR/10-bit、複数音声トラック選択、iPhone Safariは「未検証／非保証」と明記する。対応していないものは不完全出力を保存させない。
- **通常利用の推奨検証範囲：音声なし、長辺360pxまたは720px、選択区間0.5〜5秒。** UIには10秒や720p級／1080p級の実験的な選択肢が残るが、標準動作の品質保証・必須端末試験には含めず、明確な試験表示・制約のもとで提供する。公開時の標準対応画質を超える処理は性能を保証しない。
- EdgeはChromium系のため**推奨スポットチェック**とし、Edge対応を正式に表示する場合のみそのビルドの実動作確認を必須とする。iPhoneは今回の公開対象としない（将来の再評価）。それ以外のOS／ブラウザも無条件に対応と表示しない。

## 公開の必須確認（P0：欠けたら公開不可）

1. **実MP4の正しさ：** 自動CIでSTと実際のMTの短い逆再生・往復再生のフレーム順／時間／H.264 MP4再生・保存を検査。音声を使う場合は、AACの有無・トラック数・基本同期をCIで確認。不正動画やキャンセル後に不完全・古い出力を保存できない。
2. **代表的なAndroid実機の操作（最新版の配布候補）：** 実端末のH.264 MP4を使い、長辺720px以下で約5秒のReverseと約1〜3秒のPing-pongを**各1回**成功させ、MP4が端末で再生できることを確認。可能なら写真またはダウンロードから選択。中止→再試行を**1回**、保存先確認とファイル名を確認。OS・端末・ブラウザ・入力元・動画コーデック・結果を記録。異常終了／継続不能な遅延は要修正。
3. **音声：** AACを選べる実ファイルでAndroidの短い逆再生を**1回**聴き、明白なノイズ・無音・大幅な同期ずれがないことを確認する。CIの音声検査は引き続き必須。150msの厳密な実機機器測定は、問題が発見されない限り追加調査へ移す。音声非対応の素材では「音声なし」で問題なく完走する。
4. **プライバシーとデータ保護：** ユーザーの動画を外部送信しない。実HTMLのCSP・通信を確認し、単一HTML直開きSTと配信MTの動作を確認する。生成済みMP4の破棄確認、キャンセル、ファイル変更、エラー・空状態、日英UI、スマホの操作と保存が正しいこと。既知の重大な安全・データ破壊・実行不能バグは残さない。
5. **資産・ライセンス：** 今のBuilder Actions期限付き成果物は**公開用に不可**。一致するFFmpeg/x264/Emscripten等のライセンス・対応ソースを備えた再取得可能な恒久配布物とSHA-256固定を用意して確認する。配布する単一HTML、README日英、既知制限、実際の画面スクリーンショット、faviconを確認する。

## 元動画のメモリ救済経路（改訂する考え方）

元のG2「1GiB以下の入力は全量コピー禁止」は、実装済みのAndroidファイルプロバイダー救済機能と矛盾していた。**代替の安全条件案：** 通常はWORKERFSなどで全量コピーを避ける。直接読めなかった場合だけ、**64MiB以下の入力**を端末内のメモリへ一時コピーして再試行することを容認する。64MiBを超えるファイルを救済目的で全量コピーしてはならない。失敗は明示し、古い入力・中間Blobsを解放し、外部送信しない。端末の空きメモリ・ブラウザ都合による失敗はあり得るため「メモリ使用が一定以下」「すべてのAndroid提供元で動作」は保証しない。元の無コピー目標は性能改善項目として残す。

**この改訂で安全な失敗、容量上限、プライバシーの確認を免除してはならない。**

## P1（推奨だが必須ではない）とP2（追加の負荷研究）

- **P1:** 720pxの異なる実ファイル2本目、Windows Edgeの代表1ケース、Androidの別入力元・端末1機種、より広いエラー状態・アクセシビリティの手動確認。既存のデスクトップ回帰CIで十分にカバーされた組合せは繰り返し実機試験を要求しない。
- **P2:** Android／iPhone両方で720p10秒・1080p5秒を各モード3回ずつ、長時間連続変換、精密なメモリピーク計測、全VFR・回転・HEVC/HDR・音声組合せ網羅、元ファイル1GiBまで完全無コピー。**標準対応を宣言する／機能を正式サポートに昇格する場合に、その条件に合わせて再実施する。**
- 既知の問題は深刻度で評価し、P0事故（漏洩、不完全な成果物、正常範囲の基本変換失敗）は公開停止。実験的な高画質のみの性能不足は明記のうえP2として追跡してよい。
