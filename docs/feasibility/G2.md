# Gate G2 — Reverse Clip v0.6.0 memory, performance and reliability

**2026-10-13 status: INVESTIGATE / NOT PASSED.** This is a development and verification log, not a release or a physical-device performance claim. The prior [v0.5 audio Chrome CI #38358181120](https://github.com/ttomohisa/htmlapps-reverse-clip/actions/runs/38358181120) proved 298-frame H.264/AAC Ping-pong at **small resolution**; it did not prove 720p10s or 1080p5s on phones.

## Implemented candidate safeguards

| Setting | Compact | Standard / 720p-class | High / 1080p-class |
| --- | --- | --- | --- |
| Long edge max | 360px or 720px | 1280px | 1920px |
| Short edge max | Same as long edge | 720px | 1080px |
| Range | 0.5–10s | 0.5–10s | 0.5–5s |
| Output FPS | 15 (experimental) | 15 (experimental) | 15 (experimental) |
| Maximum YUV420 frame cache **estimate per chunk** | 48 MiB | 48 MiB | 48 MiB |
| 16:9 typical frames per chunk | up to 30 | 30 (~39.6 MiB) | 16 (~47.5 MiB) |
| Reverse chunks / Ping-pong chunks | at most 8 / 16 | at most 8 / 16 | at most 8 / 16 |

- The displayed quantity is a **lower-bound estimate of buffered YUV420 frames**, not process peak memory or a strict device RAM cap. Decoder, filter graph, encoder, JS, WASM heaps and browser overhead are additional. Builder's separate 96 MiB per-chunk estimate guard still applies.
- The existing Builder runner verifies per-chunk frame counts and the remux verifies a complete frame count, including 2N–2 Ping-pong output. Both presets retain aspect ratio, cap short and long edges, and never upscale. The app does not silently truncate a selected range or lower requested quality.
- Optional audio-track inspection has its own WASM instance. It is now aborted/disposed when an export starts, and may resume after the video job finishes. The audio setting remains **No audio** by default.
- Simultaneous Create calls are rejected, failed video preview clears its object URL/element and navigation/pagehide returns to the empty state so bfcache cannot revive a revoked preview.
- Both ST and MT still pin experimental Builder Actions artifact `11794061552` (expires **2026-10-20**), not an immutable corresponding-source GPL release.

## 2026-10-13 desktop ST full-HD proof — G2 STILL OPEN

The actual generated standalone **ST** HTML passed **11/11** synthetic
full-resolution H.264/AAC exports on one Linux Chromium desktop, including
three consecutive 720p10s Ping-pong operations, three consecutive 1080p5s
Ping-pong operations, optional AAC at both resolutions, a mid-conversion
cancel followed by a successful H.264/AAC retry, and decoded source-frame
identity checks across the turn and chunk boundaries. Runtimes were
approximately 10s (Reverse) and 18–22s (Ping-pong), with a summed
browser-subprocess RSS indicator roughly 727–891 MiB on this machine.
Audio+video track durations matched on both AAC samples.

**Evidence, exact measurements and important method limitations:**
[`V060_DESKTOP_ST_MEASUREMENTS.md`](V060_DESKTOP_ST_MEASUREMENTS.md).

This **does not replace pending MT full-resolution, physical Android,
Android photo-provider, memory peak or human audio quality acceptance**.
The testing container blocked ordinary file:// and loopback navigation, so
the standalone ST HTML was run using Playwright set_content; previous CI
covers its own file:// and HTTP entry points separately.

The existing Android photo/cloud provider workaround **intentionally reads and copies files up to 64 MiB** into memory before preview and processing, because some providers cannot be read in a Worker. Files above 64 MiB use WORKERFS and are never wholly loaded through `file.arrayBuffer()`; failing large provider reads give an error instead of a dangerous full-file fallback. **The original G2 condition ("no whole input copy for inputs <=1 GiB") is therefore not yet strictly satisfied for small Android selections.** Resolve by a proven alternative provider path or explicit specification approval; do not silently treat this as PASS.

## Opt-in desktop endurance harness

A reproducible full-resolution test has been added at
`tests/feasibility/v060-stress-browser-smoke.py`. This **is not executed by
regular CI** because it is potentially slow and memory-intensive, especially
for 1080p ST runs. A manual run produces real saved and FFmpeg-decoded MP4
files and a JSON report with conversion time, plus optional sampled desktop
process-tree RSS via psutil. The first Linux desktop ST full-resolution runs are now recorded in [V060_DESKTOP_ST_MEASUREMENTS.md](V060_DESKTOP_ST_MEASUREMENTS.md); full-size isolated MT and physical phone runs remain outstanding.
Start with `--profile standard --runtime ST --runs 3 --cancel-retry`;
see `tests/feasibility/README.md` for exact setup and an audio variant.
This fixture is synthetic, and desktop observations cannot close the
physical phone Gate G2.
